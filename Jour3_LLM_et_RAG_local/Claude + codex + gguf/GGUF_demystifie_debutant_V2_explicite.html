1 · Les sigles de base

IA, ML, LLM, SLM : ne mélangeons pas tout

IA — Intelligence artificielle

Terme général pour les systèmes qui réalisent des tâches habituellement associées à l’intelligence humaine : comprendre du texte, classer, prévoir, générer, etc.

ML — Machine Learning

En français : apprentissage automatique. Au lieu d’écrire toutes les règles à la main, on entraîne un modèle à partir de données.

LLM — Large Language Model

En français : grand modèle de langage. Il prédit et génère des suites de tokens. Exemples de familles : Llama, Qwen, Gemma, Mistral.

SLM — Small Language Model

En français : petit modèle de langage. Il possède généralement moins de paramètres et vise souvent une exécution plus légère.

À retenir : GGUF n’est pas un LLM. GGUF est un format de fichier pouvant contenir les poids et métadonnées d’un modèle.
IA = domaine · ML = méthode · LLM/SLM = modèles2
2 · Le matériel

CPU, GPU, RAM et VRAM : où le modèle travaille-t-il ?

CPU — Central Processing Unit

Le processeur central de l’ordinateur. Polyvalent. Il peut exécuter un modèle, mais est souvent moins rapide qu’un GPU pour les gros calculs matriciels.

GPU — Graphics Processing Unit

Le processeur graphique. Conçu pour effectuer beaucoup de calculs en parallèle. Très utile pour l’entraînement et l’inférence des modèles.

RAM — Random Access Memory

La mémoire vive principale du PC. Un modèle exécuté sur CPU y charge tout ou partie de ses données.

VRAM — Video Random Access Memory

La mémoire vidéo du GPU. Si le modèle est envoyé sur le GPU, il doit tenir totalement ou partiellement dans cette mémoire.

Exemple : un PC avec 16 Go de RAM et une carte graphique avec 8 Go de VRAM possède deux zones de mémoire différentes. Un moteur comme llama.cpp peut répartir certains calculs entre CPU et GPU.
CPU = processeur · GPU = processeur graphique · RAM/VRAM = mémoire3
3 · Anatomie d’un modèle

Paramètre, poids, tenseur : que contient réellement un modèle ?

Paramètre

Une valeur numérique apprise pendant l’entraînement. Un modèle « 8B » contient environ 8 milliards de paramètres.

Poids

Le mot « poids » désigne les valeurs apprises qui contrôlent les calculs du réseau neuronal. Dans la pratique, on parle souvent des « poids du modèle ».

Tenseur

Un tableau de nombres à plusieurs dimensions. Les poids sont organisés en tenseurs : vecteurs, matrices et blocs multidimensionnels.

Image mentale : un tableur contient des cellules ; un modèle contient énormément de nombres regroupés en tenseurs. Pendant l’inférence, le moteur effectue des opérations mathématiques sur ces nombres.
8B = environ 8 milliards de paramètres4

Unité manipulée par le modèle. Un token n’est pas obligatoirement un mot.

Tokenizer

L’outil qui transforme le texte en tokens puis reconstruit du texte à partir des tokens générés.

6 · Contexte et mémoire

Context window et KV cache : pourquoi un long prompt consomme plus ?

Context window — fenêtre de contexte

Nombre maximal de tokens que le modèle peut prendre en compte dans une séquence donnée selon sa configuration et le moteur.

KV cache — Key-Value cache

En français : cache clé-valeur. Il conserve des résultats intermédiaires de l’attention afin d’éviter de recalculer tout l’historique à chaque nouveau token.

+

Plus de contexte → plus de mémoire utilisée par le cache → parfois moins de vitesse.

La taille du fichier GGUF n’est donc pas la seule mémoire à prévoir.

Erreur fréquente : « mon fichier fait 5 Go, donc 5 Go de RAM suffisent ». Faux : il faut aussi de la marge pour le moteur, les buffers, le contexte et le système.
KV = Key-Value · le contexte augmente la mémoire d’exécution7
7 · Qu’est-ce que GGUF ?

GGUF = GGML Universal File

GGUF est un format binaire conçu pour stocker des modèles destinés à l’inférence avec GGML et des moteurs basés sur GGML.

  • GGML : bibliothèque/projet de calcul sur tenseurs à l’origine de l’écosystème de llama.cpp.
  • Universal File : l’objectif est de réunir dans un format cohérent les tenseurs et les métadonnées nécessaires au chargement.
  • Le format est pensé pour être extensible et pour permettre un chargement efficace.

8 · À l’intérieur du fichier

Que trouve-t-on concrètement dans un GGUF ?

1. En-tête

Le fichier commence par une signature permettant au logiciel d’identifier le format GGUF et sa version.

2. Métadonnées

Paires clé-valeur décrivant par exemple l’architecture, le tokenizer, des paramètres de configuration et d’autres informations.

3. Tenseurs

Nom, dimensions, type de données, emplacement puis données numériques qui représentent les poids.

mmap — memory mapping / mappage mémoire : technique qui permet au système d’exploitation de mapper le fichier dans l’espace mémoire, ce qui peut rendre le chargement plus efficace.
La spécification officielle GGUF décrit la structure : signature, version, paires clé-valeur, informations des tenseurs et bloc de données.
GGUF rassemble données du modèle + métadonnées9

11 · Base ou Instruct ?

Un modèle « Base » n’a pas le même rôle qu’un modèle « Instruct »

Base model — modèle de base

Pré-entraîné pour prédire le texte. Il peut être utile pour la recherche ou comme point de départ d’un fine-tuning, mais il n’est pas forcément optimisé pour suivre une instruction utilisateur.

Instruct model — modèle instruction

Modèle ajusté pour mieux suivre des consignes, dialoguer et répondre dans un format attendu. Pour un assistant, c’est souvent le choix le plus simple.

Fine-tuning — ajustement fin : phase d’entraînement supplémentaire qui spécialise un modèle sur des données, comportements ou tâches ciblées.
Pour un assistant débutant : commencer par une variante Instruct12

14 · Estimer la mémoire

Un calcul simple pour les poids — puis ajouter la marge

Approximation pédagogique

mémoire des poids ≈ paramètres × bits / 8

Pourquoi « / 8 » ? Parce que 8 bits = 1 octet.

ExempleCalcul simplifiéPoids théoriques
8B en 16 bits8 Md × 16 / 8≈ 16 Go
8B en 8 bits8 Md × 8 / 8≈ 8 Go
8B en 4 bits8 Md × 4 / 8≈ 4 Go
Mais ce n’est pas la consommation finale. La quantification par blocs ajoute des échelles et métadonnées ; le moteur ajoute aussi contexte, cache, buffers et structures internes.
8 bits = 1 octet · prévoir toujours une marge15

Compresser un modèle sans le zipper

Transformer les poids vers une représentation numérique plus compacte. On cherche à réduire disque et mémoire tout en gardant suffisamment de qualité.

17 · Décoder Q4_K_M

Que signifie exactement « Q4_K_M » ?

Q4

Q = Quantization. Le « 4 » indique une famille de quantification proche de 4 bits pour une grande partie des poids, avec des surcoûts de blocs et d’échelles.

K

K-quants : famille de schémas de quantification par blocs/super-blocs utilisée dans GGML/llama.cpp.

M

Medium : variante « Medium ». llama.cpp affiche ce type comme Q4_K - Medium. Le schéma peut mélanger différents types internes selon les tenseurs.

Donc : Q4_K_M n’est pas « exactement 4 bits pour chaque nombre ». C’est le nom d’un schéma de quantification avec une organisation précise des blocs et des types.
Sources : code de chargement llama.cpp (Q4_K - Medium) et README de quantification.
Q4_K_M = quantification Q4 · famille K · variante Medium18
18 · Quel niveau de quantification ?

Q4, Q5 ou Q6 : une règle de décision simple

OptionQuand la testerCompromis typique
Q4_K_MPremier essai local quand la mémoire est contrainte.Bon compromis taille / qualité dans de nombreux cas.
Q5_K_MQuand vous avez un peu plus de mémoire et souhaitez réduire la perte.Plus lourd, qualité souvent plus proche de la source.
Q6_KQuand la qualité prime et que la mémoire est suffisante.Encore plus lourd, quantification moins agressive.
Q8_0Pour garder une précision élevée avec un fichier encore quantifié.Très lourd comparé à Q4/Q5.
La bonne réponse vient du test. Une quantification acceptable en rédaction peut être insuffisante sur du code, des mathématiques ou une extraction stricte.

23 · Pourquoi partir d’une bonne précision ?

Éviter la requantification agressive

Bon chemin

BF16 / FP16 → Q4_K_M

On part d’une version de qualité élevée, puis on quantifie une fois vers la cible.

Chemin risqué

Q3 → Q4 → Q5

Changer une version déjà fortement quantifiée ne recrée pas l’information qui a été perdue.

La documentation llama.cpp avertit que la requantification de tenseurs déjà quantifiés peut fortement dégrader la qualité comparée à une quantification depuis des poids 16 ou 32 bits.
Source : README officiel de llama-quantize, option --allow-requantize.

27 · Local ou cloud ?

Local

32 · Les erreurs classiques

Ce qu’un débutant doit éviter

« Le plus gros est forcément le meilleur »

Non : coût, latence, tâche et langue comptent.

« GGUF = modèle compressé »

Pas forcément : GGUF est un format qui peut contenir différents types, y compris des représentations fortement ou peu quantifiées.

« 4 bits = exactement 4 bits par poids »

Une quantification par blocs ajoute échelles et structures ; la moyenne réelle peut être différente.

« Le modèle tient sur disque, donc il tient en RAM »

Il faut ajouter le moteur, le contexte, le KV cache, les buffers et le système.

Ne jamais confondre taille du fichier et mémoire totale d’exécution33
33 · Checklist finale

La procédure simple à suivre à chaque nouveau projet

  1. Décrire la tâche avec 20 à 100 exemples réels.
  2. Fixer les contraintes : langue, licence, données, RAM, VRAM, latence, budget.
  3. Présélectionner 2 à 5 modèles adaptés au cas d’usage.
  4. Choisir un format/runtime compatible avec votre matériel.
  5. Tester une première quantification, par exemple Q4_K_M.
  6. Mesurer qualité, TTFT, tokens/s, RAM/VRAM et coût.
  7. Comparer Q4/Q5/Q6 si la qualité ou la mémoire ne convient pas.
  8. Déployer local, cloud ou hybride selon les résultats.
Principe : choisir le plus petit système qui atteint de façon fiable votre niveau de qualité cible.
Mesurer avant de décider34
