1 · La complétion — 8 raccourcis

Le mode le plus utilisé, et le moins piloté. Ces huit raccourcis changent la façon de travailler.

#RaccourciCe qu'il faitÀ retenir
1TabAccepte toute la suggestionLe réflexe à corriger en premier : accepter sans lire
2Ctrl+→Accepte un mot seulementLe raccourci le plus sous-utilisé. On garde la vitesse et le contrôle
3ÉchapRefuse la suggestionRefuser souvent est bon signe
4Alt+]Proposition suivanteElles diffèrent vraiment. Essayez-en trois
5Alt+[Proposition précédente
6Alt+\Redemande une suggestionAprès avoir ouvert un fichier voisin
7Ctrl+EntréeOuvre le panneau de propositionsPlusieurs propositions côte à côte, comparables
8Ctrl+Alt+IOuvre le chat latéralCmd sur macOS
Le levier numéro un : ouvrir les bons onglets avant de commencer. La complétion voit les fichiers ouverts. Un fichier voisin bien écrit améliore les suggestions immédiatement, sans rien configurer.

6 · Les fichiers de configuration — 6 entrées

Le levier le plus rentable, et le plus ignoré. Tout ce qui suit se versionne : écrit une fois, cela profite à toute l'équipe.

#FichierLu quandCe qu'on y met
36.github/copilot-instructions.mdÀ chaque demandeLe projet, la langue, l'architecture, les interdits. Une page
37.github/instructions/*.instructions.mdQuand un fichier correspond à applyToLes règles propres à un dossier : tests, vues, migrations
38.github/prompts/*.prompt.mdQuand vous tapez /nomUne tâche répétitive, écrite une fois
39.github/agents/*.agent.mdQuand vous choisissez l'agentUn rôle : relecteur, testeur, explorateur
40AGENTS.mdAutomatiquementLe format ouvert, partagé avec d'autres agents
41.vscode/mcp.jsonEn mode agentVos serveurs MCP

Le squelette d'un fichier de prompt

---
mode: agent          # ask (répond) | edit (modifie) | agent (fait tout)
description: Ce que fait cette commande, en une phrase.
---

Complète la fonction `${input:fonction:nom de la fonction}`.

1. Lis le bloc JSDoc : il énonce les règles.
2. Lis les tests : ils sont la spécification exacte.
3. Écris l'implémentation.
4. Lance `node run-tests.js`.
5. Résume en trois lignes.

Contraintes : français, deux espaces d'indentation, aucune dépendance.

Le squelette d'une instruction ciblée

---
applyTo: "js/vue.js"          # ou "tests/**/*.js", "**/*.sql"
---

# Règle absolue de ce fichier

Toute valeur venue de l'utilisateur passe par `echapper()` avant d'entrer
dans une chaîne HTML. Sans exception.

#RéglagePourquoi

43chat.promptFilesActive les fichiers de prompt du dépôt
44chat.instructionsFilesLocationsOù chercher les instructions ciblées
45github.copilot.enableActiver la complétion par type de fichier

Vérifiez le réglage n° 42 maintenant. Sans lui, vous écrivez des instructions que personne ne lit — et vous concluez, à tort, qu'elles ne servent à rien.

Annexe A · Reconnaître une mauvaise suggestion en trois secondes

SignalCe que ça veut dire
Elle appelle une fonction qui n'existe pasLe modèle invente des noms plausibles. contacts.sortByAmount() n'existe pas
Elle importe une bibliothèque absente du projetlodash, moment, date-fns : il code comme sur un autre projet
Elle ne traite pas le cas videUne division sans garde, un [0] sans vérification de longueur
Elle change de langueDes noms en anglais dans un projet en français : vos instructions ne sont pas lues
Elle est trop longueVingt lignes pour une fonction qui en demandait cinq : il a inventé des besoins

Annexe B · Ce qui part réellement de votre machine

ModeCe qui est envoyé
ComplétionLe fichier courant, et des extraits des fichiers ouverts
ChatCe que vous référencez, plus les instructions du dépôt
#codebaseDes extraits trouvés par recherche dans tout le dépôt
Mode agentTout ce qu'il décide de lire. Vous ne choisissez pas
Vérifiez avec votre direction informatique ce qui est autorisé avant de pointer un assistant sur un dépôt client. Cette question relève du contrat, pas de la technique — et elle ne se rattrape pas après coup.

Réflexe suffisant dans 90 % des cas : un fichier de secrets ne doit jamais être ouvert dans un onglet pendant que vous travaillez avec un assistant.
