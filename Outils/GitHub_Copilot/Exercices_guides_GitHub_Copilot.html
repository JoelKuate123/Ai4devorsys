GitHub Copilot · Exercices guidés

Trois exercices sur MiniCRM, dix étapes. Quatre fonctions à compléter, 8 tests au rouge — votre cahier des charges.

Durée totale 3 h 00 Niveau débutant à intermédiaire Code base MiniCRM · variante squelette Tests 8 au rouge sur 90
Chaque étape tient en une action. Faites-les dans l'ordre. Les cases se cochent à l'écran et la page retient vos coches ; les zones de texte sont à remplir — c'est là que se joue l'apprentissage. Le bouton Exporter en PDF vous en donne une copie à garder.
Le projet a des trous : quatre fonctions de js/statistiques.js sont laissées à compléter, et 8 tests sont au rouge. Ces 8 échecs sont votre cahier des charges — plus précis que n'importe quelle consigne.

Avant de commencer · 10 minutes

0Installer et régler
Debutant
  1. Dans VS Code : installez les extensions GitHub Copilot et GitHub Copilot Chat.
  2. Connectez-vous. L'icône en bas à droite doit être pleine, pas barrée.
  3. Ouvrez le dossier Outils/GitHub_Copilot/codebase_minicrm.
  4. Vérifiez le réglage critique (voir ci-dessous).
// Ctrl+Shift+P -> « Preferences: Open User Settings (JSON) »
{
  // SANS CETTE LIGNE, vos fichiers d'instructions ne sont pas lus.
  "github.copilot.chat.codeGeneration.useInstructionFiles": true,
  "chat.promptFiles": true,
  "chat.instructionsFilesLocations": { ".github/instructions": true }
}
Le réglage useInstructionFiles est celui que tout le monde oublie. Sans lui, vous écrivez des instructions que personne ne lit — et vous concluez, à tort, qu'elles ne servent à rien.

Exercice 2 · Edits, agent, et relecture

Durée : 1 h 10 · En binôme

2.1Le mode Edits : deux fichiers, une demande
Intermediaire
  1. Ctrl+Shift+I.
  2. Ajoutez explicitement au contexte : js/statistiques.js et js/app.js. Ne comptez pas sur la devinette.
  3. Demandez : « implémente parMois() et affiche son résultat dans un nouveau bloc du tableau de bord ».
  4. Le résultat arrive en diff, fichier par fichier.
  5. Refusez volontairement le diff de app.js, acceptez l'autre.
  6. Observez ce qui se passe. Puis refaites et acceptez les deux.

Que se passe-t-il quand on n'accepte qu'un fichier sur deux ?

Exercice 3 · Industrialiser pour l'équipe

Durée : 50 minutes · En binôme

3.1Tester une instruction de dépôt
Debutant
  1. Dans .github/copilot-instructions.md, ajoutez une règle de style bien à vous. Par exemple : « pas de fonction fléchée en dehors des callbacks ».
  2. Demandez une nouvelle fonction, n'importe laquelle.
  3. La règle est-elle respectée ?
  4. Si non : reformulez-la. Une instruction floue est ignorée.

3.2Une instruction ciblée
Intermediaire

Créez .github/instructions/depot.instructions.md.

---
applyTo: "js/depot.js"
---

# Règle absolue de ce fichier

Ce fichier ne contient AUCUNE règle métier. Il range et il retrouve.
Toute validation appartient à modele.js.

Toute méthode qui modifie les données renvoie un objet
{ succes: boolean, erreurs?: object } — jamais un booléen nu,
jamais une exception. L'appelant doit pouvoir afficher un message.
  1. Demandez une nouvelle méthode dans depot.js.
  2. Demandez ensuite la même chose dans modele.js.
  3. L'instruction s'est-elle appliquée uniquement au bon fichier ?
3.3Un fichier de prompt réutilisable
Avance

Créez .github/prompts/ajouter-champ.prompt.md. Il doit ajouter un champ au modèle, de bout en bout.

---
mode: agent
description: Ajoute un champ à un contact, de la validation à l'affichage.
---

Ajoute le champ `${input:champ:nom du champ}` à un contact.

Touche ces cinq endroits, dans cet ordre :

1. `js/modele.js` — normalisation dans normaliserContact(),
   et validation dans validerContact() si le champ a des contraintes.
2. `tests/modele.test.js` — un test nominal, un cas limite, un cas d'erreur.
3. `index.html` — un champ dans le formulaire, avec son label.
4. `js/app.js` — la lecture du champ dans enregistrerContact()
   et son remplissage dans ouvrirFormulaire().
5. `js/vue.js` — l'affichage dans ligneContact(), passé par echapper().

Lance ensuite `node run-tests.js`. Les 90 tests doivent rester au vert.
Résume en cinq lignes ce que tu as fait, fichier par fichier.
  1. Lancez : /ajouter-champ telephone.
  2. Relisez les cinq diffs.
  3. node run-tests.js.
  4. Ouvrez index.html : le champ est-il utilisable de bout en bout ?

A-t-il oublié l'un des cinq endroits ? Lequel ?
