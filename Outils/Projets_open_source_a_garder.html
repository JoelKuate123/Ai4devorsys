Les projets open source à garder quand on est développeur

Une sélection par domaine — front, back, données et IA, architecture, outillage. Le critère n'est pas la popularité, c'est la durée de vie. Cochez ce que vous connaissez : la colonne vide est votre plan de lecture.

Formation L'IA pour les développeurs Dossier Bonus Mise à jour septembre 2026
Une sélection, pas un annuaire. Le critère retenu n'est pas la popularité : c'est la durée de vie. Chacun de ces projets est là depuis des années, a une gouvernance claire, et a des chances raisonnables d'être encore là dans cinq ans. Cochez ce que vous connaissez déjà : la colonne vide est votre plan de lecture.
Avant d'ajouter une dépendance, trois questions. Depuis combien de temps le projet existe-t-il ? Combien de personnes ont le droit de publier une version ? Que se passe-t-il si le mainteneur principal s'arrête demain ? Un projet brillant maintenu par une seule personne est un risque, pas une aubaine — et cela n'a rien à voir avec la qualité de son code.

1 · Front — l'interface

Les socles

ProjetCe que c'estPourquoi le garder
ReactLa bibliothèque d'interface la plus répandueCe n'est pas la meilleure sur tous les points, mais c'est celle que votre prochain collègue connaîtra. L'écosystème est son vrai atout.
VueL'alternative la plus lisibleCourbe d'apprentissage plus douce, documentation exemplaire. Excellent premier framework pour une équipe qui vient du HTML/CSS.
SvelteCompile au lieu d'embarquer un moteurLe code produit est petit et rapide. À regarder pour un site public où le poids de la page compte vraiment.
AstroSites orientés contenu, JavaScript minimalUne documentation, un blog, un site vitrine : il envoie zéro JavaScript par défaut. Le bon outil pour ce que 80 % des sites font réellement.
htmxL'interactivité sans frameworkDes attributs HTML au lieu d'une application cliente. À connaître ne serait-ce que pour se rappeler qu'un framework n'est pas toujours nécessaire.

Le style et les composants

ProjetCe que c'estPourquoi le garder
Tailwind CSSDes classes utilitaires plutôt qu'une feuille de styleDivise beaucoup les débats de nommage en équipe. On aime ou on déteste ; il faut l'avoir essayé pour avoir un avis.
Open PropsDes variables CSS prêtes à l'emploiCouleurs, ombres, espacements, animations. Du CSS standard, aucune dépendance à l'exécution.
Radix / Headless UIDes composants sans style, mais accessiblesLe clavier, les rôles ARIA et le focus sont traités correctement — ce qui prend des semaines à faire soi-même, et que presque personne ne fait bien.
Shoelace / Web AwesomeDes composants web natifsFonctionnent dans n'importe quel framework, et sans framework. Utile quand on ne veut pas parier sur un écosystème.

La visualisation

ProjetCe que c'estPourquoi le garder
D3La référence de la visualisation de donnéesDifficile, mais rien ne fait ce qu'il fait. À connaître, même si on utilise autre chose au quotidien.
Observable PlotLa couche simple au-dessus de D3Un graphique correct en trois lignes. Le bon choix pour 90 % des besoins.
Chart.jsDes graphiques classiques, sans effortBarres, lignes, camemberts. Documentation claire, résultat honnête.
MermaidDes diagrammes écrits en texteUn organigramme, une séquence, une architecture — versionnés avec le code, donc à jour. GitHub et GitLab les affichent nativement.

2 · Back — le serveur

Les frameworks

ProjetLangagePourquoi le garder
FastAPIPythonUne API documentée automatiquement, avec validation des données. Le chemin le plus court entre une idée et une API propre.
DjangoPythonTout est fourni : administration, authentification, migrations. Le bon choix quand le métier compte plus que l'architecture.
Express / FastifyNode.jsLe minimum, et le minimum rapide. Fastify quand la charge compte.
Spring BootJavaL'incontournable en entreprise. Verbeux, mais personne n'est jamais licencié pour l'avoir choisi.
LaravelPHPPHP moderne, écosystème très complet. À ne pas mépriser : il fait tourner une part énorme du web.
Go / net-httpGoLa bibliothèque standard suffit souvent. Binaire unique, déploiement trivial.

Les bases de données

ProjetCe que c'estPourquoi le garder
PostgreSQLLa base relationnelle de référenceLe choix par défaut. JSON, recherche plein texte, vecteurs, géographie : il fait presque tout, correctement, depuis trente ans.
SQLiteUne base dans un fichierSous-estimée. Pour un outil interne, une application de bureau, des tests, elle est souvent le meilleur choix — et le plus simple à sauvegarder.
Redis / ValkeyCache et files en mémoireSessions, verrous, files d'attente. Valkey est la continuation ouverte de Redis, à surveiller.
DuckDBL'analytique, dans un fichierInterroge un CSV ou un Parquet de plusieurs gigaoctets en SQL, sans serveur. Remplace beaucoup de scripts pandas.
pgvectorLes vecteurs, dans PostgreSQLPour un RAG d'entreprise : inutile d'ajouter une base vectorielle dédiée si vous avez déjà PostgreSQL.

Les files et le temps

ProjetCe que c'estPourquoi le garder
RabbitMQMessagerie entre servicesÉprouvé, bien documenté, opérable par une petite équipe.
KafkaFlux d'événements à grande échellePuissant et coûteux à exploiter. À ne sortir que si le volume le justifie vraiment — ce qui est plus rare qu'on ne le croit.
TemporalOrchestration de traitements longsReprend un traitement là où il s'est arrêté, même après un redémarrage. Précieux pour les chaînes d'IA qui durent des minutes.

3 · Données et IA

ProjetCe que c'estPourquoi le garder
pandasLa manipulation de données en PythonL'outil que tout le monde connaît. Ses défauts sont documentés, ses recettes aussi.
PolarsL'alternative rapide à pandasBeaucoup plus rapide sur les gros volumes, API plus cohérente. La transition vaut le coup sur un projet neuf.
Apache Arrow / ParquetLe format d'échange de donnéesUn CSV de 2 Go devient un Parquet de 200 Mo, lisible dix fois plus vite. À connaître dès qu'on manipule des données sérieusement.
scikit-learnL'apprentissage automatique classiqueAvant de sortir un LLM : une régression ou un arbre de décision résolvent beaucoup de problèmes, pour mille fois moins cher.
Hugging Face transformersExécuter des modèlesLe point de passage obligé. Modèles, jeux de données, et une communauté qui documente tout.
sentence-transformersLes modèles d'embeddingPetits, rapides, économiques. Le cœur de tout RAG sérieux.
llama.cppExécuter un LLM sur du matériel modesteLe moteur derrière LM Studio et Ollama. Le format GGUF vient de là.
OllamaUn modèle local en une commandeollama run mistral et c'est parti. La façon la plus simple de tester du local.
LangChain / LlamaIndexFrameworks d'application IAUtiles pour prototyper vite. À réévaluer avant la production : beaucoup d'équipes finissent par écrire les cinquante lignes elles-mêmes.
Chroma / QdrantBases vectorielles dédiéesSi vous n'avez pas déjà PostgreSQL. Chroma pour commencer, Qdrant pour passer à l'échelle.
RagasÉvaluer un RAGLe sujet dont personne ne parle. Sans mesure, on ne sait pas si une modification améliore ou dégrade le système.
Le réflexe qui fait la différence : avant de sortir un LLM, demandez-vous si une expression régulière, une requête SQL ou une régression logistique ne ferait pas l'affaire. Elles sont plus rapides, moins chères, déterministes, et elles n'inventent rien.

4 · Architecture, exploitation, sécurité

Empaqueter et déployer

ProjetCe que c'estPourquoi le garder
DockerEmpaqueter une application avec son environnementLe standard. Même si vous ne l'aimez pas, vos collègues l'utilisent.
PodmanDocker sans démon privilégiéCompatible avec les mêmes images, sans processus root permanent. Souvent la seule option acceptée en environnement contraint.
KubernetesOrchestration de conteneursÀ connaître pour savoir quand ne pas l'utiliser. Trois conteneurs et deux serveurs ne justifient pas Kubernetes.
Terraform / OpenTofuL'infrastructure décrite dans des fichiersL'infrastructure devient relisable, versionnée et reproductible. OpenTofu est la continuation entièrement ouverte.
CaddyServeur web avec HTTPS automatiqueDeux lignes de configuration, certificat renouvelé tout seul. Une alternative sérieuse à nginx pour les petits déploiements.

Observer

ProjetCe que c'estPourquoi le garder
OpenTelemetryLa norme de télémétrieTraces, métriques et journaux, dans un format unique. Instrumentez une fois, changez d'outil ensuite sans tout réécrire.
Prometheus + GrafanaMétriques et tableaux de bordLe duo classique. Une alerte qui fonctionne vaut mieux qu'un tableau de bord que personne ne regarde.
SentryLe suivi des erreursVersion auto-hébergeable disponible. Savoir qu'une erreur s'est produite avant que le client n'appelle change tout.

Sécurité et qualité

ProjetCe que c'estPourquoi le garder
OWASP Top 10 / ASVSLa référence des risques applicatifsCe n'est pas un outil, c'est une liste. La lire une fois par an suffit à éviter la majorité des incidents.
TrivyScanner d'images et de dépendancesUne commande, un rapport. À brancher dans l'intégration continue.
gitleaksDétecte les secrets dans un dépôtÀ installer en pré-commit aujourd'hui. Un secret publié est un secret compromis, même supprimé cinq minutes plus tard.
pre-commitDes vérifications avant chaque commitFormatage, secrets, taille des fichiers. Empêche les erreurs bêtes d'atteindre le dépôt.
SemgrepAnalyse statique par règles lisiblesOn écrit ses propres règles en quelques lignes. Utile pour faire respecter une règle maison — par exemple : « jamais d'innerHTML sans échappement ».

mise / asdfGérer les versions de langagesLa bonne version de Node et de Python par projet, automatiquement.
PlaywrightTests de bout en bout dans un navigateurRapide, fiable, multi-navigateurs. Le meilleur de sa catégorie aujourd'hui.
VitestTests unitaires en JavaScriptRapide, compatible avec l'API de Jest. Le choix par défaut sur un projet neuf.
pytestTests en PythonSimple à écrire, extensible à l'infini. C'est celui de la journée 3.
RuffFormatage et analyse PythonRemplace une demi-douzaine d'outils, et il est très rapide.
