2 · Bac à sable et approbations — 7 entrées

Les deux réglages qui décident de ce qu'il a le droit de faire. Tout le reste vient après.

#EntréeCe que ça faitÀ retenir
9--sandbox read-onlyLecture seuleExplorer un dépôt inconnu, faire une revue, poser des questions
10--sandbox workspace-writeÉcriture dans le dossier de travailLe mode de travail normal
11--sandbox danger-full-accessTout le disque, et le réseauUn conteneur jetable. Jamais votre poste
12-a on-requestIl demande quand il estime en avoir besoinLe bon équilibre
13-a on-failureIl demande seulement après un échecTâche longue et cadrée, sur une branche
14-a neverIl ne demande jamaisUniquement associé à read-only, ou dans un conteneur
15/permissionsChange le réglage sans quitter la sessionUtile quand la tâche change de nature en cours de route
--dangerously-bypass-approvals-and-sandbox (alias --yolo) désactive les deux protections d'un coup. Le nom est explicite : c'est une option de conteneur jetable, pas de poste de travail.

Le vrai risque n'est pas que l'agent soit malveillant : c'est qu'il exécute avec zèle une instruction mal comprise, sans garde-fou entre elle et votre disque.

Le squelette d'une commande maison

# .codex/prompts/corriger-un-bogue.md

Corrige UN SEUL défaut, celui qui concerne : $1

1. Lance `node run-tests.js` et identifie le test en échec.
2. Lis le test : il dit ce qui est attendu. Ne le modifie pas.
3. Explique la CAUSE en deux phrases, AVANT de toucher au code.
4. Fais la correction la PLUS PETITE possible.
5. Relance : ce test passe, aucun autre ne casse.
6. Propose un message de commit d'une ligne, en français.

Si le test te semble faux, dis-le et arrête-toi.

7 · Automatiser et déléguer — 6 entrées

#CommandeCe qu'elle faitÀ retenir
41codex exec "…"Une tâche, aucune interactionLe mode script
42codex exec --jsonSortie exploitable par un programmeIntégration continue
43codex resumeReprend une sessionSans repartir de zéro
44codex forkDuplique une sessionExplorer deux pistes
45codex cloudLance une tâche dans le cloudTâche longue, environnement reproductible
46codex applyApplique localement le diff d'une tâche cloudRelisez-le comme les autres
Le risque de la délégation n'est pas technique, il est humain : plus le travail est distant, moins on le relit. Règle simple : une tâche déléguée doit être vérifiable automatiquement. « Fais passer les tests » se délègue. « Améliore l'architecture » ne se délègue pas.

Annexe B · La pile de configuration, du plus fort au plus faible

  1. Les options de la ligne de commande et --config
  2. La configuration du projet — .codex/config.toml
  3. Le profil nommé — ~/.codex/<profil>.config.toml
  4. Votre configuration personnelle — ~/.codex/config.toml
  5. Les valeurs gérées par l'organisation
  6. La configuration système — /etc/codex/config.toml
  7. Les valeurs par défaut de l'outil
/debug-config affiche cette pile telle qu'elle est réellement résolue chez vous. C'est la commande à lancer quand un réglage « ne prend pas ».

Annexe C · Les quatre fichiers à créer dans un projet

FichierVersionné ?Ce qu'on y met

~/.codex/config.tomlNonVos préférences personnelles, tous projets
Ce qui compte le plus dans AGENTS.md : les commandes. Un agent qui ne sait pas comment lancer vos tests travaille à l'aveugle, et vous rendra du code plausible sans aucun signal de qualité.
