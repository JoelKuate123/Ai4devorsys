Atelier des techniques de prompt

Chaque technique est une fonction du fichier techniques-de-prompt.js. Modifiez les champs, regardez le prompt se construire, et envoyez-le au modèle. Sans clé d'API, le mode hors ligne prend le relais.

1 · Le role prompting

Quand : presque toujours. Pourquoi ça marche : un modèle produit le texte le plus probable ; en lui donnant un métier, on déplace la zone de probabilité vers le vocabulaire et les réflexes de ce métier.

2 · Le few-shot prompting

Quand : dès que le format compte plus que le raisonnement. Deux ou trois exemples valent mieux qu'un paragraphe de consignes, parce qu'un exemple ne laisse aucune place à l'interprétation.

3 · Le chain-of-thought

Quand : calculs, diagnostics, choix d'architecture. Quand surtout pas : reformulation, traduction, extraction — on paie des tokens de raisonnement pour rien.

4 · Imposer le format de sortie

Quand : dès que la réponse doit être lue par un programme et non par un humain. C'est la technique qui transforme un chatbot en composant logiciel.

5 · La self-consistency

Quand : une décision qui compte, et un modèle qui hésite. Le prix : N appels au lieu d'un. Toujours un nombre impair de votes. 

(cliquez pour lancer)

6 · Le prompt de modification

L'erreur de débutant : « améliore ce code ». Le modèle réécrit tout, renomme, supprime des cas, et vous ne savez plus ce qui a bougé. La bonne façon : dire ce qui change et ce qui ne doit pas changer.

Travaux pratiques · la spécification « bonnes nouvelles »

Énoncé : « Faire un prompt de spécification d'une application web qui donne les nouvelles positives du jour. » On ne code pas l'application : on écrit le prompt, et on vérifie que la spécification obtenue est utilisable. 

(cliquez pour voir le résultat)
Ce que ce TP démontre : on ne demande jamais un document au modèle, on demande une donnée structurée qu'on peut vérifier, puis on la met en forme soi-même. Un JSON se contrôle en onze lignes de code ; un texte libre ne se contrôle pas.
