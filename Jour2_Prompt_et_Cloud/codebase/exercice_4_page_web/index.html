Exercice 4 · Module 4

Construire et déployer une page, sans écrire de code

Énoncé du programme : « développer et déployer une application web uniquement à l'aide d'un assistant IA de développement ». Vous produirez du HTML et du CSS par prompt, vous les relirez, et vous mettrez le résultat en ligne — sans compte, sans carte bancaire, en trois minutes.

1 · Le cahier des charges

Une page unique, « Bonnes Nouvelles », qui présente trois nouvelles positives du jour. Rien de plus.

ÉlémentCe qui est attendu

Trois nouvellesChacune : un titre, deux lignes de résumé, la source

2 · Le prompt de départ

Tu es un intégrateur web expérimenté.

Produis UNE page HTML complète et autonome : « Bonnes Nouvelles »,
une page qui présente trois nouvelles positives du jour.

STRUCTURE
- un en-tête avec un titre h1 et une phrase d'accroche ;
- trois blocs « nouvelle », chacun avec un titre h2, deux lignes de résumé
  et le nom de la source ;
- une section « Pourquoi cette page » de trois lignes ;
- un pied de page avec la date et une adresse de contact.

CONTRAINTES DE FORME
- un seul fichier, du <!DOCTYPE html> à </html> ;
- le CSS dans une balise <style> dans le <head> ;
- AUCUN JavaScript ;
- aucune dépendance externe : pas de CDN, pas de police distante, pas d'image ;
- lang="fr", meta charset, meta viewport ;
- une seule colonne sous 700 pixels ;
- contraste suffisant, taille de texte d'au moins 16 pixels.

CONTENU
Invente trois nouvelles plausibles, et écris explicitement
« exemple fictif » à côté de chaque source.

Réponds UNIQUEMENT par le code de la page.
Notez la dernière consigne de contenu. On demande au modèle d'étiqueter ce qu'il invente. Une page qui présente des nouvelles fabriquées comme si elles étaient réelles, même en exercice, est une fausse information. Prenez l'habitude maintenant.

3 · Les trois tours

Tour 1Obtenir une page qui s'affiche

Collez le prompt, récupérez le code, enregistrez-le sous bonnes-nouvelles.html dans ce dossier, ouvrez-le. Passez la grille de contrôle du jour 1 (les sept points) : combien sur 7 ?

Tour 2Faire une modification cadrée

Utilisez le prompt de modification vu à l'exercice 3 : collez votre page, demandez un changement, et listez ce qui ne doit pas bouger. Par exemple : « ajoute une quatrième nouvelle » ou « passe le fond en sombre ».

Puis lisez la liste des changements que le modèle annonce, et vérifiez-la : a-t-il touché à autre chose ?

Tour 3Mettre en ligne

Trois options, toutes gratuites, sans carte bancaire.

ServiceCommentCe qu'il faut savoir
Netlify Drop Glissez le dossier sur app.netlify.com/drop. L'adresse s'affiche en trente secondes. Le plus rapide. Aucun compte nécessaire pour un essai.
GitHub Pages Un dépôt, un fichier index.html, puis Settings → Pages. Demande un compte GitHub, mais votre page est versionnée.
Cloudflare Pages Même principe, depuis un dépôt Git. Rapide partout dans le monde, y compris depuis l'Afrique.
Ce que vous venez de faire est exactement ce que fait une agence pour une page vitrine : rédiger, relire, publier. La différence est que vous n'avez pas écrit le HTML — vous l'avez commandé et vérifié.

4 · Ce que ça coûterait, si l'IA tournait dans la page

Votre page est statique : elle ne coûte rien à l'usage. Mais si l'application classait automatiquement des titres d'actualité, il y aurait un appel de modèle par titre, et une facture.

Le scénario : 200 titres classés par jour. Chaque appel envoie environ 600 tokens (le message système compte à chaque fois) et en reçoit 20.

ModèleUsage typiqueCoût mensuelDécision
Modèle local (LM Studio)Confidentiel, volume illimité0,00 $Gratuit au token, mais il faut une machine
Petit modèle rapideClasser, extraire, router≈ 1,30 $Le bon choix pour cette tâche
Modèle économiqueVolume élevé≈ 6,00 $Acceptable
Modèle généralisteUsage général≈ 12,00 $Sur-dimensionné
Modèle de rédactionRédaction exigeante≈ 24,00 $Injustifiable ici
Modèle de raisonnementRaisonnement complexe≈ 60,00 $Quarante-six fois le nécessaire
La formule tient en une ligne : coût = (tokens ÷ 1 000 000) × prix du million. Tout le reste n'est que de la mise en forme. Le tableau de calcul à remplir avec vos chiffres est dans votre fiche participant.
Le piège que tout le monde oublie : le message système est envoyé à chaque appel. Sur une tâche courte, c'est lui qui pèse le plus lourd dans la facture — trois phrases de plus multiplient le coût.

Classer un titre en trois catégories est une tâche fermée. Un petit modèle avec quatre bons exemples la réussit aussi bien qu'un grand. Le surcoût n'achète rien.

5 · Et la clé d'API, alors ?

Question du module 4, et elle se pose dès qu'on met quelque chose en ligne. Trois architectures, trois réponses.

ArchitectureOù vit la cléVerdict
Page statique qui appellerait le modèle elle-même Dans le code de la page, visible par tous (clic droit → code source) Jamais. Une clé publiée est une clé compromise, et les robots scannent en continu.
Page statique + modèle local (LM Studio) Nulle part : le modèle tourne chez l'utilisateur Convient à un usage interne ou à une démonstration.
Page statique + votre serveur + le modèle Sur votre serveur, jamais dans le navigateur La seule architecture acceptable en production.
L'architecture tient en une ligne : navigateur → votre serveur → le modèle. La clé s'arrête au milieu. Une couche de plus, et le problème disparaît.
