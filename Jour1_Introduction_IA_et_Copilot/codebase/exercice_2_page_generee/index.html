Exercice 2 · Module 2

Générer une page web à partir d'un prompt

Vous n'écrirez pas de JavaScript. Vous écrirez un prompt, vous le donnerez à Copilot ou à un assistant de chat, et vous récupérerez du HTML et du CSS. Puis vous ferez le seul travail qui compte vraiment : relire ce qui revient.

1 · Le prompt de départ

Copiez ce texte tel quel. Il est volontairement complet : c'est ce qui le distingue d'un « fais-moi une page pour un club de sport ». 

Tu es un intégrateur web expérimenté.

Produis UNE page HTML complète et autonome pour :
un club de sport de quartier, avec ses horaires et un formulaire de contact.

CONTRAINTES DE FORME
- un seul fichier, du <!DOCTYPE html> à la balise </html> ;
- le CSS dans une balise <style> à l'intérieur du <head> ;
- aucune dépendance externe : pas de CDN, pas de police distante, pas d'image distante ;
- aucun JavaScript.

CONTRAINTES DE CONTENU
- le texte est en français, l'attribut lang vaut "fr" ;
- l'encodage est déclaré : <meta charset="utf-8"> ;
- la page s'adapte au mobile : <meta name="viewport"…> et une seule colonne sous 700 pixels ;
- un titre <h1> unique, et des sous-titres <h2> pour chaque section ;
- couleur dominante : vert profond. Ton : chaleureux et familial.

Réponds UNIQUEMENT par le code de la page.
Aucune phrase avant, aucune phrase après.
Comptez les lignes. Votre demande tient en une phrase ; le prompt en fait vingt. C'est là que se joue la qualité du résultat — pas dans le modèle que vous avez choisi.

Ne collez jamais de code d'entreprise dans un chat public. Cette page d'exercice ne contient rien de confidentiel, mais prenez l'habitude dès aujourd'hui : la question se pose avant de coller, jamais après.

3 · Où l'enregistrer

  1. Ouvrez gabarit.html dans VS Code.
  2. Effacez tout, collez le code obtenu.
  3. Enregistrez-le sous le nom ma-page.html, dans ce dossier.
  4. Double-cliquez dessus : il s'ouvre dans votre navigateur.
Le raccourci qui fait gagner la journée : dans VS Code, installez l'extension Live Preview de Microsoft. Un clic droit sur le fichier, Show Preview, et la page se recharge toute seule à chaque enregistrement. Plus besoin d'aller cliquer dans le navigateur.

4 · La grille de contrôle

Sept contrôles. Ouvrez votre page dans le navigateur, puis affichez son code source (Ctrl+U) et cochez ce qui est vrai.

Notez votre score sur 7 dans votre fiche participant.

Ce score est le vrai livrable de l'exercice. Il ne mesure pas la qualité du modèle : il mesure l'écart entre ce que vous avez demandé et ce que vous avez reçu. C'est la seule façon de savoir si un prompt s'améliore ou se dégrade.

5 · Le second tour

Reprenez votre prompt et ajoutez une contrainte de votre choix. Par exemple :

  • « le fond est sombre et le texte clair » ;
  • « chaque section a une icône dessinée en CSS, sans image » ;
  • « les horaires sont dans un tableau <table> » ;
  • « le formulaire a des <label> reliés à leurs champs ».

Relancez, recomptez. Votre contrainte a-t-elle été respectée ? Et les sept contrôles précédents tiennent-ils toujours ?

Le piège classique : en ajoutant une contrainte, le modèle en oublie une autre. C'est pour cela qu'on garde une grille — et qu'on la refait à chaque tour.

6 · Les deux fichiers de référence

À remplir

gabarit.html

Le squelette commenté. Effacez tout, collez le résultat du modèle, enregistrez sous ma-page.html.

 Référence

exemple_reussi.html

Une page qui obtient 7/7. Comparez-la à la vôtre, contrôle par contrôle.

Ce que cet exercice démontre

  • Le prompt fait le résultat. Vingt lignes de contraintes valent mieux qu'un grand modèle mal instruit.
  • Le modèle oublie. Toujours. Ce n'est pas un défaut à corriger, c'est une propriété à surveiller.
  • Mesurer, pas ressentir. « C'est mieux » n'est pas une évaluation. « 6/7 au lieu de 4/7 » en est une.
